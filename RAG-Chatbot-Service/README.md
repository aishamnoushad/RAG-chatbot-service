# RAG Chatbot Service

A backend microservice for storing and managing chat histories generated by chatbot system.
This service provides comprehensive session and message management with secure API access, rate limiting, and full containerization support.

## 🚀 Features

### Core Functionalities
- ✅ **Session Management**: Create, read, update, and delete chat sessions
- ✅ **Message Storage**: Store messages with sender, content, and optional context
- ✅ **Session Operations**: Rename sessions, mark/unmark as favorite
- ✅ **Pagination Support**: Efficient data retrieval with pagination
- ✅ **User Isolation**: Secure user-based data access
- ✅ **API Key Authentication**: Secure access with X-API-Key header
- ✅ **Rate Limiting**: Built-in request rate limiting
- ✅ **Health Monitoring**: Comprehensive health checks and monitoring
- ✅ **Database Migrations**: Automatic schema management with Flyway

## 🛠️ Technology Stack

- **Framework**: Spring Boot 3.5.6
- **Language**: Java 21
- **Database**: PostgreSQL 16
- **Security**: Spring Security with API Key authentication
- **Rate Limiting**: Bucket4j
- **Documentation**: Swagger/OpenAPI 3
- **Containerization**: Docker & Docker Compose
- **Build Tool**: Maven
- **Testing**: JUnit 5, Mockito
- **Database Migration**: Flyway
- **Monitoring**: Spring Boot Actuator

## 🏃‍♂️ Quick Start

### Prerequisites
- Docker Desktop installed and running
- Docker Compose v2.0 or higher

### 1. Clone the Repository
```bash
git clone <repository-url>
cd RAG-Chatbot-Service
```

### 2. Environment Configuration
Copy the environment template and customize:
```bash
cp .env.example .env
```

Edit the `.env` file with your configuration:
```bash
# Database Configuration
POSTGRES_DB=rag-chat-db
POSTGRES_USER=raguser
POSTGRES_PASSWORD=rag@123
POSTGRES_PORT=5432

# Application Configuration
SERVER_PORT=8087
APP_PORT=8087

# API Configuration
API_KEY=your-secure-api-key-here

# Rate Limiting Configuration
RATE_LIMIT_REQUESTS_PER_MINUTE=60

# PgAdmin Configuration (optional)
PGADMIN_DEFAULT_EMAIL=admin@example.com
PGADMIN_DEFAULT_PASSWORD=admin123
PGADMIN_PORT=5050
```

### 3. Start the Application
```bash
# Using Docker Compose
docker-compose up --build

# Or use the provided script
./start.sh
```
# To stop the application

```bash
# stop the container
docker compose down -v

```
### 4. Access the Services
- **Application**: http://localhost:8087
- **API Documentation**: http://localhost:8087/swagger-ui.html
- **Health Check**: http://localhost:8087/actuator/health
- **PgAdmin**: http://localhost:5050

## 📚 API Endpoints

### Authentication
All API endpoints require the `X-API-Key` header with a valid API key.

### Chat Sessions (`/api/sessions`)

| Method | Endpoint | Description |
|--------|----------|-------------|
| `POST` | `/api/sessions` | Create a new chat session |
| `GET` | `/api/sessions/user/{userId}` | Get all sessions for a user |
| `GET` | `/api/sessions/user/{userId}/paginated` | Get paginated sessions for a user |
| `GET` | `/api/sessions/{sessionId}` | Get a specific session |
| `PUT` | `/api/sessions/{sessionId}` | Update a session (rename, favorite) |
| `DELETE` | `/api/sessions/{sessionId}` | Delete a session and all messages |

### Chat Messages (`/api/messages`)

| Method | Endpoint | Description |
|--------|----------|-------------|
| `POST` | `/api/messages` | Add a message to a session |
| `GET` | `/api/messages/session/{sessionId}` | Get all messages for a session |
| `GET` | `/api/messages/session/{sessionId}/paginated` | Get paginated messages for a session |
| `GET` | `/api/messages/session/{sessionId}/user/{userId}` | Get messages with user validation |
| `GET` | `/api/messages/session/{sessionId}/user/{userId}/paginated` | Get paginated messages with user validation |
| `DELETE` | `/api/messages/{sessionId}` | Delete all messages in a session |

### Health & Monitoring (`/actuator`)

| Method | Endpoint | Description |
|--------|----------|-------------|
| `GET` | `/actuator/health` | Application health status |
| `GET` | `/actuator/info` | Application information |
| `GET` | `/actuator/env` | Environment properties |


## 🔐 Security

### API Key Authentication
- All endpoints require the `X-API-Key` header
- API key is configured via environment variable `API_KEY`
- Invalid or missing API keys return HTTP 401

### Rate Limiting
- Configurable requests per minute (default: 60)
- Rate limiting is applied per IP address
- Exceeded limits return HTTP 429

### Excluded Endpoints
The following endpoints don't require API key authentication:
- `/actuator/health`
- `/actuator/info`
- `/swagger-ui/**`
- `/v3/api-docs/**`

## 🗄️ Database Schema

### Chat Sessions Table
- `id` (BIGINT, Primary Key)
- `user_id` (VARCHAR, Not Null)
- `title` (VARCHAR, Not Null)
- `is_favorite` (BOOLEAN, Default: false)
- `created_at` (TIMESTAMP)
- `updated_at` (TIMESTAMP)

### Chat Messages Table
- `id` (BIGINT, Primary Key)
- `session_id` (BIGINT, Foreign Key)
- `content` (TEXT, Not Null)
- `context` (VARCHAR)
- `sender` (ENUM: USER, ASSISTANT)
- `created_at` (TIMESTAMP)
